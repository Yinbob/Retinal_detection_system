### 2.2 已发现的实现细节

1. 实际文件名是小写 `vistel0_left_0.jpg`，任务书示例使用大写 V。解析表达式需兼容大小写，读取路径保留实际拼写。
2. 采样号有 10、11。必须转成整数排序，不能按字符串排序。
3. 血管 PNG 每张均包含 0–255 灰度值，并非只有 0/255。可当作血管强度图；若算法需要二值图，应显式比较阈值。其是否为校准过的概率图尚无依据，不能称为血管真值。
4. 一个抽查样本中非零像素约占 57.3%，大于 127 的像素约占 6.4%。这只是单图统计，已足以说明 `vessel > 0` 不适合作为默认二值化。
5. 样图中 `vistel0_left_0` 与 `vistel0_left_1` 的视盘水平位置明显不同；部分其他组也有位置异常。可能来自镜像、裁切、采集差异或标签问题，尚未定论。先记录可疑样本，不改标签，不自动删除，也不默认翻转所有左眼。
6. 基础路线不使用 `odfovea.json` 和 EW 结果。若后续使用，需单列“带额外标注/派生数据”的实验；不能假设 FIRE 有同等输入。

## 3 统一数据契约

### 3.1 图像清单

先统一成 `manifest.csv`，算法不关心原始文件命名。

```python
from dataclasses import dataclass
from typing import Literal

@dataclass(frozen=True)
class ImageRecord:
    image_id: str
    dataset: Literal["vistel", "fire"]
    image_path: str          # 解压后的相对路径；审计清单另存 ZIP member
    vessel_path: str | None
    subject_id: str | None
    eye: str | None
    identity_id: str | None  # vistel: "vistel:0:left"
    sample_index: int | None
    role: Literal["query", "gallery"]
    pair_id: str | None      # FIRE 的图像对，不自动视作身份
    category: str | None     # FIRE 的 S/P/A
    content_sha256: str
```

Vistel 解析核心如下。

```python
PATTERN = re.compile(
    r"^vistel(?P<subject>\d+)_(?P<eye>left|right)_(?P<index>\d+)\.(jpg|jpeg|png)$",
    re.IGNORECASE,
)

groups = group_by(records, key=lambda r: (r.subject_id, r.eye))
for identity, images in groups.items():
    images = sorted(images, key=lambda r: (r.sample_index, r.image_id))
    assert len(images) >= 2, f"no reference for {identity}"
    query = images[0]       # 编号最小，不硬编码永远等于 0
    gallery = images[1:]
```

正式清单保存 query/gallery 的实际路径、身份和哈希；参考集来自所有身份，不能根据查询文件名里的员工号或眼别提前筛选。标签仅供划分与评测使用，特征提取器和匹配器只接收图像数组或提取出的特征。

### 3.2 检索协议

```python
@dataclass(frozen=True)
class RetrievalProtocol:
    query_ids: tuple[str, ...]
    gallery_ids: tuple[str, ...]
    positive_reference_ids: dict[str, frozenset[str]]
    label_semantics: str    # "same_eye" 或 "designated_pair"
    protocol_hash: str
```

Vistel 中 `positive_reference_ids[q]` 是参考集中所有与 q 同人同眼的图像，不能只认某一张。比较两种方法时验证 `protocol_hash` 一致。

### 3.3 FIRE 补齐后的适配

按任务书先实现解析 `(?P<pair>[SPA]\d+)_(?P<slot>[12])\.jpg` 的能力：slot=2 为 query，slot=1 为 gallery。实际目录、大小写、额外后缀在收到文件后核实。预期输入包含彩照、ROI 掩膜、对应点；缺少对应点不影响基础身份检索，只影响附加配准评估。

FIRE 原始论文说明 129 幅源图组成 134 对，同一只眼可形成多个图像对；这不是 134 个身份。S/P/A 分别为 71/49/14 对，代表不同重叠度或解剖变化条件，属于原始论文描述，不能代替本地文件统计。[FIRE 原始论文](https://www.aivojournal.com/index.php/AIVO/article/download/42/90/540)

适配器需要处理两种标签语义：

- 有可靠同眼映射：填 `identity_id`，计算与 Vistel 同义的同人同眼准确率。
- 只有文件配对：填 `positive_reference_ids` 为指定配对参考图，先计算“指定配对参考图命中率”，单独命名。它不等同于完整身份准确率：同眼的其他参考图也可能是正确身份。最终课程表格应在明确教学数据的映射或计分解释后生成。

不能把不同 pair_id 自动当作负身份；不能用测试图相似度聚类反过来制造真值。显式配对和完全重复图像可以提供同眼关系，但所得连通分量未必覆盖所有同眼关系；不同分量也不能据此直接标成异眼。

FIRE 到齐时执行：统计实体文件和源图哈希；审计 `_2` 与全部 `_1` 是否存在相同源图；记录 query/reference 数量和跨集合重复。若有源图重用，保留课程协议记录，并增加排除查询自身副本的评测；两种分母和参考集都需明确。不要静默去重后仍沿用原始样本数。

`control_points_*` 只供最终配准误差测量，不能在测试时用于估计候选变换、选择正确参考图或调阈值。SuperRetina 仓库对 P37 对应点给出了异常提示；只在附加的配准指标中核实、记录处理规则，不据此删除课程身份检索中的该查询。[数据说明](https://github.com/ruc-aimc-lab/SuperRetina/blob/main/data/README.md)

## 5 预处理与两条基础算法

### 5.1 共用预处理

基础输入统一为彩照，先建立能在两个数据集运行的路线，再做 Vistel 血管图扩展。

1. 解码为 RGB uint8；失败应记录并中止数据准备，不能默默减少正式测试分母。
2. 根据彩照亮度初估 FOV，取最大连通区域并填孔，获得眼底有效区。初始亮度阈值 10/255 只是候选值；在参考图上检查暗图是否被误裁。背景阈值不是身份接受阈值。
3. 按 FOV 外接框裁切、保持长宽比缩放并补边到 1024×1024。FOV 为空时记录问题，不回退为全黑有效图。
4. 提取绿色通道作为基础灰度表示，对其使用 CLAHE，初始 `clipLimit=2.0, tileGridSize=(8,8)`。
5. FOV 掩膜只取 0/255，重采样用最近邻；彩照用面积或线性插值，血管灰度强度图用线性插值。
6. 掩膜边缘内缩初始 8 像素，减少黑色圆边形成的关键点和梯度。HOG 额外清零掩膜外区域及外围梯度单元，尽量避免仅凭圆形边缘区分图像。

消融时逐项关闭 CLAHE、FOV 裁切或改为常规灰度，其他参数固定。方法特定的内部尺寸可以不同，但输入来源、课程协议和公共预处理版本一致，并在结果中记录。

### 5.2 关键点基础方案 SIFT 与 RANSAC

流程：SIFT 提取 → L2 描述子匹配 → 最近邻比值筛选 → RANSAC 单应性检验 → 每对图像得分 → 全库取最高分参考图。

初始提取配置：`nfeatures=1500, contrastThreshold=0.02, edgeThreshold=10, sigma=1.6`。这些是待验证起点，不是已确定最优值。

OpenCV 官方文档提供 `SIFT_create`、`knnMatch`、L2 与比值筛选的用法；几何教程说明 `findHomography` 至少需要四组对应点，并返回内点掩膜。课程方案额外采用至少 8 个候选和至少 8 个内点的起始质量门槛，以减少少量偶然匹配得高分。[特征匹配](https://docs.opencv.org/4.x/dc/dc3/tutorial_py_matcher.html)、[几何一致性](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html)

```python
sift = cv2.SIFT_create(
    nfeatures=1500, contrastThreshold=0.02,
    edgeThreshold=10, sigma=1.6,
)
keypoints, descriptors = sift.detectAndCompute(gray_u8, fov_u8)

# compare_local 内部；省略数据类构造和可视化
if descriptors_q is None or descriptors_r is None:
    return invalid_pair("no_descriptors")
if len(descriptors_q) < 2 or len(descriptors_r) < 2:
    return invalid_pair("too_few_descriptors")

neighbors = cv2.BFMatcher(cv2.NORM_L2).knnMatch(
    descriptors_q, descriptors_r, k=2,
)
good = [pair[0] for pair in neighbors
        if len(pair) == 2
        and pair[0].distance < ratio * pair[1].distance]
if len(good) < min_matches:
    return invalid_pair("too_few_matches")

src = np.float32([xy_q[m.queryIdx] for m in good]).reshape(-1, 1, 2)
dst = np.float32([xy_r[m.trainIdx] for m in good]).reshape(-1, 1, 2)
H, inliers = cv2.findHomography(
    src, dst, cv2.RANSAC, ransac_px,
    maxIters=2000, confidence=0.995,
)
if H is None or inliers is None or not np.isfinite(H).all():
    return invalid_pair("geometry_failed")
n_inliers = int(inliers.sum())
if n_inliers < min_inliers:
    return invalid_pair("too_few_inliers")
# 还应检查投影坐标有限、矩阵非退化，并保存重投影误差。
score = float(n_inliers)
```

基础排序使用内点数 `score = n_inliers`，相同分数时依次比较内点比例、重投影误差和固定图像 ID。无效配对不参与排序，全部无效则返回 `reference_id=None` 并计入错误，不能返回参考列表第一张。

初始比值阈值 0.75 表示 `最近邻距离 < 0.75 × 次近邻距离`；RANSAC 初始 3 像素，指预处理后的 1024 像素坐标系中的重投影残差。它们都不是图像接受阈值。

改进候选：双向比值筛选后取互相一致的匹配；按关键点数量归一化；加入内点空间覆盖度；对比部分仿射与单应性。先选择一项针对观察到的错误，避免同时修改所有环节无法解释收益。

单应性只是几何一致性的近似模型，不保证视网膜在所有视角下严格符合平面变换。FIRE 低重叠组和结构变化组需单独查看失败原因。

### 5.3 全局基础方案 HOG 与余弦相似度

流程：公共灰度表示 → 内部缩放到 512×512 → 全图 HOG → L2 归一化 → 余弦相似度 → 返回最高分参考图。

```python
from skimage.feature import hog

x = cv2.resize(gray_u8, (512, 512), interpolation=cv2.INTER_AREA)
v = hog(
    x.astype(np.float32) / 255.0,
    orientations=9,
    pixels_per_cell=(16, 16),
    cells_per_block=(2, 2),
    block_norm="L2-Hys",
    feature_vector=True,
    channel_axis=None,
).astype(np.float32)
norm = np.linalg.norm(v)
if not np.isfinite(norm) or norm < 1e-12:
    return invalid_feature("zero_or_nonfinite_vector")
v = v / norm

# 每行一个参考向量；所有向量均已经 L2 归一化。
scores = gallery_matrix @ query_vector
```

该配置输出 `(32-1)×(32-1)×2×2×9 = 34596` 维固定向量，符合全局图像表示要求；无需分类器训练。具体 API 以 [scikit-image HOG 文档](https://scikit-image.org/docs/stable/api/skimage.feature.html#skimage.feature.hog) 为依据。

归一化后点积就是余弦相似度，越大越相似。它与 SIFT 内点数的尺度不同，不能共用一个数值接受阈值。HOG 可能对旋转、位移、局部重叠变化较敏感，需要用实际错误检验，不预设其准确率。

全局方案保持独立：不能先用 SIFT 对每个候选做配准、再把 HOG 的结果当作独立全局基线。若尝试此流程，应命名为融合方案，单列结果。

### 5.4 Vistel 血管图扩展

优先尝试把血管灰度图作为 HOG 的输入，或供 SIFT 提取特征，保持身份清单不变。灰度输入先保留强度，不强制二值化。需要骨架/分叉点时，再比较固定阈值 64、128、192 或参考集上选定的自动阈值策略。

该扩展只能表明“给定这些血管派生图时的表现”。FIRE 的 ROI 掩膜是有效区域掩膜，不是血管分割图，不能直接用来补齐血管输入。要形成跨数据集一致的血管路线，需给两个数据集使用同一个血管提取器，并计入提取时间及模型来源。

## 6 检索判定和评价指标

课程核心过程如下，候选生成与真值评测必须分开。

```python
for query_id in protocol.query_ids:
    query = load_cached_features(query_id)
    candidates = []
    for reference_id in protocol.gallery_ids:
        result = compare(query, load_cached_features(reference_id))
        save_pair_result(query_id, reference_id, result)
        if result.valid:
            candidates.append((reference_id, result))
    prediction = rank_or_fail(candidates)
    save_prediction(query_id, prediction)

# 只有评测模块接触 positive_reference_ids。
correct = sum(
    pred.reference_id in protocol.positive_reference_ids[pred.query_id]
    for pred in predictions
)
accuracy = correct / len(protocol.query_ids)
```

主表报告完整参考集的 Top-1 同眼准确率、正确数与测试总数。Vistel 为 `correct/40`，因此单张样本带来 2.5 个百分点变化；引用结果必须带分子分母，不能只报百分比。

额外输出带拒识的结果：最高有效得分大于等于方法自己的 `accept_threshold` 才接受，否则返回拒绝。已注册用户被拒绝也算失败，不能从分母排除。

| 指标 | 用途 | 计数单位 |
|---|---|---|
| Top-1 准确率 | 课程主比较 | 查询图 / 眼 |
| 带拒识识别准确率 | 检查阈值后的识别结果 | 查询图 / 眼 |
| 拒绝数、无有效匹配数 | 解释失败 | 查询图 / 眼 |
| 同眼/异眼分数分布、ROC、FAR/FRR | 可选阈值分析 | 图像对 |
| 查询耗时 median/p95 | 比较计算代价 | 查询图，包含全库搜索 |
| 特征提取时间和缓存体积 | 比较离线成本 | 图像与整库 |
| FIRE S/P/A 分组准确率 | 解释场景差异 | 查询图，补齐后统计 |

FAR/FRR 的配对定义必须明确，不能把配对 FAR 写成全库搜索下的陌生人误接受率。所有课程查询都有正确参考，因此仅靠主实验不能完整评估未注册用户拒识；要做这项扩展，需另设按员工隔离的未注册查询协议，不能把它混进主结果。

每只眼参考图数量不均衡时，先按任务书返回最相似的单张参考图，身份得分等于该身份参考图最大值。不擅自减少参考图或改为多数投票。参考数量偏差可以用另设的单参考补充实验分析。

## 7 调参和错误分析的先后顺序

### 7.1 保护正式测试图

Vistel 的 40 张最小编号图保留为正式 query，不用来网格搜索。彩照文件审计和少量样图查看已进行，但尚未根据正式查询成绩选择算法配置；这不是完全盲测，应在需要时如实记录。

推荐先用参考图建立代理开发协议：每眼从原参考图中取编号最小的一张作为代理 query，剩余原参考图作代理 gallery。只有总图像数至少 3 的眼参与代理 query，共 33 只眼；原本只有一张参考图的 7 只眼仅保留为代理 gallery 的干扰候选。这样代理 gallery 为 158−33 = 125 张，且每个代理 query 至少有一张同眼参考。代理 query 不得同时出现在代理 gallery 中。

代理协议与正式协议的身份有重叠，而且每眼参考图更少，不能把代理分数称为新身份泛化结果，也不能保证阈值直接迁移最优。它的作用是避免对 40 张正式查询图反复挑选参数。

先固定代理清单；按员工把代理查询分为 5 组，左右眼一起分组，每组尽量均衡。各组使用同一代理 gallery，分别记录准确率和配对分数，以发现参数对员工或参考数量是否敏感。这是开发稳定性检查，不是独立的主体外测试，也不额外训练分类器。

### 7.2 搜索空间与选择准则

先使用上述初值完成连通性验证，然后仅在代理协议上分阶段搜索。

| 参数 | 候选 | 固定条件 |
|---|---|---|
| SIFT 最近邻比值 | 0.70 / 0.75 / 0.80 | 先固定 1024 尺寸、1500 特征 |
| RANSAC 残差 | 2 / 3 / 5 像素 | 只在处理坐标系比较 |
| 最低内点数 | 6 / 8 / 12 | 与最低候选数分开记录 |
| HOG 单元大小 | 16 / 32 | 512 尺寸、9 方向、2×2 block 固定 |
| CLAHE | 关闭 / clip=2 / clip=4 | 初轮仅对胜出的各方法配置比较 |
| 血管阈值 | 64 / 128 / 192 | 只用于明确需要二值图的扩展 |

SIFT 初轮 3×3=9 组，先固定最低内点 8；胜出后再比较 3 个最低内点候选。不要一开始做所有预处理、尺寸、特征数量的笛卡尔积。HOG 初轮 2 组，然后做预处理比较。

基线算法参数以代理 Top-1 准确率选择；并列时依次选查询耗时更低、参数更接近初值的方案。保存全部候选成绩，不只保留胜出配置。

接受阈值可在代理同眼/异眼配对分数上选择：候选为观察分数之间的边界以及全接受/全拒绝端点，选择代理 FAR≤1% 下 FRR 最低者，若并列取更保守的阈值。1% 是本计划建议的分析目标，不是课程规定或安全保证；两种方法阈值各自标定。小样本下同时报告正负对数、FAR/FRR 原始计数及无效匹配数。

不能在只有已注册查询的 Top-1 准确率上不断降低接受阈值并称其为良好的拒识校准，也不能把参考图代理阈值的配对 FAR 当作正式图库搜索 FAR。

### 7.3 冻结与改进

1. 冻结基础方案配置、代理清单和正式协议哈希。
2. 正式运行两条基础方案，保存全部查询预测及错误。
3. 分析错误：低对比度、视野偏移、疑似镜像、几何匹配失败、局部错误匹配、全局向量区分不足、参考数量不均衡等。视觉现象不直接上升为医学诊断。
4. 根据开发证据选择一项改进，在代理集或预先保留的员工组上验证，保留原始基线。
5. 若根据正式测试错误设计改进，再次在同一测试集报告的收益应注明“对该测试集错误分析后的改进”，不能称作未见测试泛化。后续到齐且未用于开发的 FIRE 可以作为跨数据集验证，但其输入与身份语义必须先核实。

## 8 缓存、结果文件和复现

特征提取每张只执行一次，不在 6320 个配对中重复提取。SIFT 按图缓存 `.npz`，HOG 可保存整库 float32 矩阵和图像 ID 索引。198×34596×4 约 26.1 MiB，不需要向量数据库。

缓存键至少包括：源图内容哈希、预处理配置、特征配置、实现版本、依赖版本；选择血管输入或镜像变体时也纳入键。匹配参数变化可复用特征，但 RANSAC 残差或 ratio 变化必须重算相关配对阶段。

每个 `artifacts/runs/<run_id>/` 输出：

```text
resolved_config.yaml        # 含 seed、全部隐含默认值、阈值及其来源
run_meta.json               # 协议/数据/代码哈希、依赖、硬件、计时口径
queries.csv                 # 正式或代理查询清单
gallery.csv                 # 参考清单
pair_scores.csv             # 每对图像的分数、状态、匹配统计及耗时
predictions.csv             # 每查询一行，包括失败和拒绝
metrics.json                # 分子分母、准确率、耗时、分组结果
errors.csv                  # 真实身份、预测身份、候选排名、人工原因标注
figures/                    # 方法对比、分数分布、错误案例
progress.json               # 已处理查询数、最近更新时间、运行状态
```

`predictions.csv` 字段建议为：

```text
run_id,dataset,method,query_id,true_identity,pred_reference_id,
pred_identity,best_score,second_identity_score,score_margin,
accepted,correct_top1,correct_with_reject,status,query_time_ms
```

`second_identity_score` 应是次高的不同身份候选，而不是同一身份的第二张参考图；该字段只在身份真值完整的数据集上用于诊断，基础预测不依赖它。若未来用其拒识，需要明确实际部署如何获得图库身份以及独立调参。

固定 Python/NumPy/OpenCV 随机种子，RANSAC 调用前设定种子，记录线程数、平台及 OpenCV 构建信息。相同配置尽量复现预测，不能承诺跨平台 RANSAC 位级一致。耗时同时区分冷启动特征提取和缓存后全库搜索；两种方法使用相同硬件和计时口径。

运行监控以 `progress.json` 和进程状态为准，先对代理集少量查询估算时间，再设置运行超时；可暂用 30 分钟作为试跑上限，超时不是算法失败率。失败时保留日志与未完成状态，不输出伪完整的主表。

## 12 实现顺序和每步验收

这是建议的 8–10 个工作日安排，可按小组人数调整，未承诺具体自然日截止时间。

| 阶段 | 预计工作量 | 交付及验收 |
|---|---|---|
| 1 数据层 | 1 日 | ZIP 安全读取/解压、清单、40/158 划分、198 对彩照血管对应；任何不符立即定位 |
| 2 公共预处理 | 0.5–1 日 | 展示暗图/偏移图的 FOV 和增强效果，坐标映射正确 |
| 3 SIFT 基础 | 1–2 日 | 代理 query 全库检索、内点图、无特征及退化几何处理 |
| 4 HOG 基础 | 0.5–1 日 | 固定维度、向量归一化、代理检索，与 SIFT 共用评测器 |
| 5 调参冻结 | 1 日 | 33/125 代理协议、完整搜索记录、各方法冻结配置 |
| 6 Vistel 正式结果 | 1 日 | 每方法40行预测、6320行配对、正确数/40、错误案例 |
| 7 FIRE 接入 | 文件到齐后1–2日 | 本地统计、身份语义、重复审计、同协议两种方法结果 |
| 8 改进及材料 | 1–2 日 | 一项有证据的改进；四组主结果图表；代码运行说明 |

必须覆盖的功能检查：

- 文件名大小写、ID 不连续、采样号 2 与 10 的数值排序；单图身份应明确报错。
- 图像数量、每眼一张 query、query 不在 gallery、每 query 有正参考；彩照和血管图对应完整。
- 同人异眼必须算错；同眼任意参考图均算对；全部匹配失败仍保留在分母。
- 两种方法协议哈希一致；预测每查询恰好一行；无效图像不会悄悄缩小分母。
- SIFT 无描述子、kNN不足两个邻居、几何估计失败；HOG 零向量和非有限分数。
- 合成的已知排名输入检查评测器能得到预期正确数；打乱标签后的下降仅是泄漏诊断，不是正式算法结果。
- FIRE `designated_pair` 与 `same_eye` 指标名称不可混用；缺失身份映射时 same_eye 模式明确报错。
- 生成过的真实特征缓存可重复加载，改预处理后不会误用旧缓存。

暂不开发网页界面和复杂账号系统；它们不是任务书列出的算法与实验要求。先让命令行得到可复核的参考图、判断和错误案例。
